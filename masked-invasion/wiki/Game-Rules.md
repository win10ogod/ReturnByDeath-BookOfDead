# 30 項遊戲規則

[首頁](README.md) · [指令](Commands.md) · [遊戲規則](Game-Rules.md) · [常用範例](Recipes.md) · [型態池](Form-Pool.md) · [疑難排解](Troubleshooting.md)

所有規則皆為世界共用設定，可在建立／編輯世界的「遊戲規則」找到「假面入侵」，或由等級 2+ 的管理員使用 `/gamerule`。這裡的範圍為指令接受的數值範圍，不代表建議使用極端值。

```mcfunction
/gamerule miIntervalDays
/gamerule miIntervalDays 5
```

不填數值是查詢；填值是修改。規則名稱區分大小寫，布林值使用 `true`／`false`。20 TPS 時，20 tick = 1 秒、1200 tick = 1 分鐘、24000 tick = 1 遊戲日；伺服器變慢時，tick 計時也會變慢。

## 排程與勝敗

| 規則 | 預設 | 可填範圍 | 用途 |
|---|---|---|---|
| `miEnabled` | `true` | `true / false` | 啟用玩法；關閉取消現有入侵並停止入侵時鐘。 |
| `miIntervalDays` | `3` | `1～2147483647` | 入侵間隔，單位為遊戲日；睡眠跳時計入。 |
| `miWarningTicks` | `600` | `0～2147483647` | 開戰前預告 tick；600 = 30 秒，0 = 無預告。 |
| `miDefenseTicks` | `18000` | `0～2147483647` | 防守時限 tick；18000 = 15 分鐘，0 = 不限時。 |
| `miPlayerDeathFailsRaid` | `true` | `true / false` | 防守者死亡是否使入侵失敗；不會關閉死歸本體的死亡能力。 |
| `miHoldCheckpointDuringRaid` | `true` | `true / false` | 存在入侵事件時延後自動更新世界回歸點。 |

## 戰區與召回

| 規則 | 預設 | 可填範圍 | 用途 |
|---|---|---|---|
| `miArenaRadius` | `48` | `8～1024` | 以領隊鎖定重生點為中心的水平半徑，單位為格。 |
| `miArenaHeight` | `24` | `4～512` | 中心上下各允許多少格，不是總高度。 |
| `miRecallAtStart` | `true` | `true / false` | 開戰時召回防守者。 |
| `miConfinePlayers` | `true` | `true / false` | 戰鬥中越界召回及跨維度封鎖。 |
| `miBoundaryParticles` | `true` | `true / false` | 顯示戰區邊界粒子。 |

## 數量與型態階級

| 規則 | 預設 | 可填範圍 | 用途 |
|---|---|---|---|
| `miBaseRaiders` | `4` | `1～10000` | 數量公式的基礎名額，預設首波基礎／派生 4 名。 |
| `miFirstEnhancedMin` | `1` | `0～10000` | 每場強化基數隨機值的下限，預設 1。 |
| `miFirstEnhancedMax` | `2` | `0～10000` | 強化基數上限；小於下限時按下限處理。 |
| `miRaidersPerWave` | `2` | `0～10000` | 每增加一個波次，增加的敵人數量。 |
| `miRaidersPerExtraPlayer` | `2` | `0～10000` | 共同防守中，每位額外玩家增加的數量。 |
| `miMaxRaiders` | `32` | `1～10000` | 每場入侵總人數上限。 |
| `miSuperFormsFromWave` | `4` | `1～2147483647` | 開始安排超級型態的波次。 |
| `miFinalFormsFromWave` | `8` | `1～2147483647` | 開始安排最終型態的波次。 |

## 生命與攻擊

| 規則 | 預設 | 可填範圍 | 用途 |
|---|---|---|---|
| `miBaseHealth` | `40` | `1～1024` | 生命基礎值；再乘型態倍率及波次成長，40 點相當於 20 顆心。 |
| `miBaseDamage` | `3` | `1～2048` | 攻擊基礎值；再乘型態倍率及波次成長，另受武器及原模組影響。 |
| `miHealthGrowthPercent` | `15` | `0～10000` | 每波生命線性成長百分比，基準為第 1 波。 |
| `miDamageGrowthPercent` | `10` | `0～10000` | 每波攻擊線性成長百分比，基準為第 1 波。 |

## 生成與技能

| 規則 | 預設 | 可填範圍 | 用途 |
|---|---|---|---|
| `miSpawnMinDistance` | `6` | `1～1024` | 生成距離下限（格），會限制在可用範圍內。 |
| `miSpawnMaxDistance` | `20` | `1～1024` | 生成距離上限（格），最多使用戰區半徑減 2；須有已載入安全位置。 |
| `miSpawnPerSecond` | `4` | `1～100` | 每 20 個伺服器 tick 最多生成幾名入侵者。 |
| `miRiderSkills` | `true` | `true / false` | 允許本模組主動觸發原生騎士踢擊／拳擊。 |
| `miSkillIntervalTicks` | `200` | `20～2147483647` | 技能嘗試間隔 tick；200 = 10 秒，仍須符合距離、視線及原生冷卻。 |

## 掉落與獎勵

| 規則 | 預設 | 可填範圍 | 用途 |
|---|---|---|---|
| `miEquipmentDrops` | `false` | `true / false` | 新生成入侵者是否設定為掉落身上裝備。 |
| `miVictoryEmeralds` | `3` | `0～10000` | 勝利時每位防守者的綠寶石獎勵，0 = 無獎勵；離線者之後上線補發。 |

## 數量與成長怎麼算

```text
強化基數 = miFirstEnhancedMin ～ max(miFirstEnhancedMin, miFirstEnhancedMax) 的隨機整數
總數 = min(miMaxRaiders,
           miBaseRaiders + 強化基數
           + (波次 − 1) × miRaidersPerWave
           + (防守人數 − 1) × miRaidersPerExtraPlayer)
```

所以預設單人第 1 波為 5～6 名，雙人為 7～8 名。強化基數每場重新抽取，不是只在第一場抽一次；高波次會將部分名額配置成更高階型態。降低總數上限也可能限制可分配的強化／大將名額。

在第 4／8 波門檻前後，系統會依波次安排超級／最終型態，再從該階級依權重抽選。型態門檻不會額外突破總人數上限。

生命／攻擊成長採 `1 + (波次 − 1) × 百分比 / 100`，不是每波複利；例如 15% 的第 4 波是 1.45 倍。型態倍率、武器與腰帶效果另計，詳見[型態池](Form-Pool.md)。

## 什麼時候生效

| 設定 | 生效時機 |
|---|---|
| 入侵間隔 `miIntervalDays` | 在線生存／冒險玩家的等待時間約每 20 tick 按新舊間隔差額調整；不重新給完整準備期。離線玩家回來後才處理 |
| 戰區半徑／高度、預告、防守時限、總數與階級門檻 | 新入侵事件建立時決定；正在預告或防守的事件不會回寫 |
| 基礎生命／攻擊、成長倍率、裝備掉落 | 入侵者生成時設定；已生成敵人保持原屬性及掉落設定 |
| 生成距離、每秒生成數量 | 後續生成批次讀取；仍受該事件已鎖定的戰區限制 |
| 技能啟用 | 後續技能判斷使用新值；已發動技能不會撤銷 |
| 技能間隔 | 新生成敵人及下一次技能成功觸發時使用新值；不重設已在跑的冷卻 |
| 開戰召回 | 預告結束、準備進入防守時讀取 |
| 戰區封鎖、死亡失敗、邊界粒子、回歸點延後 | 後續對應事件／tick 檢查使用新值 |
| 勝利獎勵 | 勝利結算時讀取 |
| `miEnabled false` | 後續伺服器 tick 取消目前事件，並停止入侵時鐘 |

規則及進度保存在世界內，死亡回歸後會恢復回歸點中的值。`reload` 只處理型態 JSON，不會代替修改遊戲規則。

`miHoldCheckpointDuringRaid true` 會在有入侵事件時保留戰前回歸點，包含準備、預告及失敗等待階段；所有事件結束後才解除此項阻擋。恢復自動存檔仍需滿足死亡回歸本體的其他條件。

找不到生成位置時會重試，之後可能使用靠近重生點的安全空位，因此最小生成距離並非所有地形下的硬性保證。
