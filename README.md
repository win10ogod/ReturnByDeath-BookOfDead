# 死亡回歸與死者之書

Minecraft **1.21.1** · NeoForge **21.1.235** · Java **21**

[下載模組](https://github.com/win10ogod/ReturnByDeath-BookOfDead/releases/latest) · [自動建置](https://github.com/win10ogod/ReturnByDeath-BookOfDead/actions)

死亡後回到共同回歸點，保留跨輪迴記憶。死者之書記錄生前經歷，讀者按順序追體驗，直至死亡的失聲與黑暗。

## 0.7.9：玩家親自替村民命名

**對準可互動距離內的村民，按 N → 輸入名字 →「確認命名」。** 命名鍵可在「選項 → 控制 → 按鍵綁定 → 死亡回歸與死者之書」修改。任何一般玩家都能使用，不需要管理員權限、命名牌或其他物品；不占用村民交易或騎士村民的 Shift＋右鍵管理操作。

名字完全由玩家輸入。取消或按 Esc 不會改名；確認後由伺服器保存並同步，後來產生的死者之書使用死亡時的姓名。名字隨世界存檔和回歸點保存；回歸後恢復該回歸點中的名字。舊書保留當時記下的文字。

本版撤除 0.7.8 的自動取名與旅人編號替換，村民不再於出生、載入或交談時被自動改名。已存在的名字會保留，玩家可自行重新輸入。遊戲規則 `rbdPlayerNameVillagers` 預設 true；`rbdVillagerNameMaxLength` 預設 32 個字，可調整。伺服器拒絕超距離、隔牆、無效文字、過期世界介面，以及會蓋掉朋友剛改好名字的舊提交。

退出遊戲後替換為 `rbd-0.7.9.jar`，房主、朋友與專服一起更新。整合包相容模組沿用 1.1.4。

通過 29 項 NeoForge GameTest 與 Java 自測；55 模組雙客戶端實際按命名鍵、輸入中文並確認／取消，非 OP 的朋友也能操作。玩家取的名字、未命名狀態和騎士村民同伴資料在自動存檔及死亡回歸後保持一致，兩人全程保留原連線。實測為 Linux／Xvfb、本機 LAN，未另驗證 Windows 輸入法或 Radmin。

## 0.7.7：回歸點存檔提示

開始建立或更新回歸點時，畫面右下方顯示「正在存檔…」；伺服器完成後顯示「回歸點已更新」，約 5 秒後消失。房主與朋友都能看到同一輪存檔狀態，提示在世界暫停保存時仍可顯示。若存檔流程回報錯誤，則顯示「存檔未完成」。

提示預設顯示，不新增遊戲規則選項。僅在回歸點存檔時通知，死者之書的日常記憶取樣不會刷屏。死亡回歸不會誤顯示為新存檔，離線後清除提示。記憶預設 100 tick、回歸點預設 10 分鐘與連線協定 7 沿用。

更新為 `rbd-0.7.7.jar` 即可使用新提示；房主、朋友與專服一起替換舊 RBD JAR。整合包的渲染快取修補仍由相容模組 1.1.4 提供。

## 0.7.6：減少記憶封存與讀取的暫存記憶體

記憶影像直接串流序列化至壓縮檔，讀取時也改用串流解析，減少完整 JSON 字串與整行文字的重複配置。片段封存後解除寫入器引用；背景 I/O 失敗時保留原始原因，避免清理例外掩蓋它。

原解析度、無損 PNG、歷史記憶與遊戲規則沿用：記憶預設每 100 tick 一次，世界回歸點預設每 10 分鐘更新，網路協定維持 7。退出遊戲後將舊 RBD JAR 替換為 `rbd-0.7.6.jar`，房主、朋友及專服一起更新。

通過 Java 自測、26 項 NeoForge GameTest，以及 49 模組雙客戶端的 40 項自動存檔、死亡回歸和騎士空手攻擊檢查。新增低記憶體測試：相同的完整 1920×1080 隨機 PNG 資料，在 48 MiB JVM 堆積中，0.7.5 寫入時耗盡記憶體，0.7.6 完整寫入並讀回 16 筆；舊版生物記憶與玩家 PNG 記憶也逐筆比對一致。

這證實的是封存與解析步驟的額外配置改善。新舊版在基地存檔副本上各掛機 25 分鐘、各完成兩次正常自動存檔並保持連線，都沒有重現約 8 小時後的 16 GiB 堆積耗盡；尚未確認整晚 OOM 的唯一原因，也未證實整個遊戲常駐記憶體下降。掛機測試使用 Linux Java 21.0.11、10 GiB 堆積、1080p、視距 12／模擬 8、FPS 上限 60及本機 loopback；客人早期死亡，房主持續留在基地，不能替代兩名活躍玩家在 Windows／Radmin 的整晚驗證。

## 0.7.5：減少記憶影像與實體卸載對遊戲執行緒的負擔

第一人稱記憶的影像翻轉、縮放與像素複製移至背景工作執行緒，與原有 PNG 編碼一起處理。伺服器收到的影像分段也改在背景依序組裝、驗證，遊戲執行緒只套用完成的影像。普通 F2 截圖維持原行為；GPU 畫面讀回仍需在渲染執行緒執行。

實體卸載時不再等待記憶檔案寫完，改為排程封存；死亡、讀取與世界存檔仍保留必要的寫入完成檢查。死亡回歸後排隊中的控制訊息會取得目前的玩家物件，避免使用回歸前的舊物件。

保留原有解析度、無損 PNG、記憶內容與取樣設定：記憶預設每 100 tick 一次，世界回歸點預設每 10 分鐘更新。網路協定維持 7，建議房主、朋友與專服一起替換為 `rbd-0.7.5.jar`。

通過 26 項 NeoForge GameTest、Java 自測，以及 49 模組雙客戶端的 40 項檢查，涵蓋自動存檔、死亡回歸、影像與死亡終幕讀回，以及變身後普通空手攻擊；兩名玩家均保持原連線。六組 GPU 截圖測試共比對 2,266,870 個像素，PNG 與原流程逐位元組相同。

同一主機、受限傳輸的雙客戶端短測中，整體 FPS 基本相同，尚未重現玩家回報的偶發 1～5 秒停頓；本版不宣稱已排除該停頓的所有原因。完整世界存檔與死亡回歸仍會暫停世界模擬。

## 0.7.4：修正記憶封存後寫入造成的世界暫停

修正記憶感知讀取地形時，實體離開／卸載等事件先封存原片段，返回後仍嘗試追加記憶而出現 `Sealed memory segment` 的錯誤。感知完成後重新取得可寫入的片段，保留既有封存內容、當次記憶與後續連接；死亡若已在感知途中完成，不再追加死亡後的續格。

新增四項遊戲內回歸測試，涵蓋離開後繼續記錄、實際卸載、死亡最後取樣，以及感知期間死亡。修正前的三項重現均出現相同例外；修正版通過全部 25 項 NeoForge GameTest、Java 自測與 49 模組雙人測試的 18 項自動存檔／死亡回歸檢查，兩人登入次數各為 1。

記憶預設 100 tick、世界回歸點預設 10 分鐘，網路協定維持 7。退出遊戲後將舊 RBD JAR 替換為 `rbd-0.7.4.jar`。已留下故障標記的世界仍需先備份、驗證記憶及存檔，再處理該次故障；本版不會自動略過存檔完整性檢查。

## 0.7.3：每 100 tick 記憶取樣與多人影像傳輸

記憶預設改成每 **100 tick（20 TPS 時每 5 秒）**掃描並保存一次，角色狀態、感知及影像均遵守間隔，兩次取樣之間不再逐 tick 寫入續格。死亡仍立即補記最後身體狀態；播放新記憶時保留取樣時長與死亡終幕。這是明確的取樣頻率調整，不是同等逐 tick 錄製下的效能比較。

在建立／編輯世界的「遊戲規則」設定 `rbdMemoryRecordIntervalTicks`；現有世界未設定此新規則時也使用 100。管理員可執行 `/gamerule rbdMemoryRecordIntervalTicks 100`。既有 `rbdMemoryImageIntervalTicks` 作為額外影像間隔，實際擷取間隔取兩者較大值。將兩者設為 1 可使用每 tick 錄製，但 CPU、網路與儲存需求會顯著增加。

影像上傳由獨立背景執行緒處理，每批等待伺服器收妥確認；不再一次把整張影像的所有封包排入遊戲連線。尚未送出的 PNG 暫存於客戶端 `.rbd-upload`，送達後刪除，連線／世界切換時清理當次暫存。PNG 編碼與暫存不等待網路確認，登出也不在遊戲執行緒排空上傳。GPU 擷取仍需在渲染執行緒進行；編碼／存檔佇列仍有原本的記憶體預算，極慢磁碟或過高錄製頻率仍可能造成等待。

回歸點仍預設每 10 分鐘更新，完整世界副本預設各保留一份。記憶取樣降低資料增長速度，已保存的死者之書歷史仍會隨遊玩累積；低上傳頻寬時，本機待傳資料也會暫時增加。

多人連線協定更新為 7，房主、朋友及專服必須一起更新 RBD 0.7.3。先退出遊戲，再替換舊版 `rbd-*.jar`，同一個 `mods` 資料夾只保留一份 RBD。舊世界與舊記憶仍可讀取。

0.7.3 通過 21 項 NeoForge GameTest、81 項影像佇列檢查、31 項 Python 儲存／遷移測試，以及 18 項雙人自動存檔／死亡回歸檢查；兩人登入次數各為 1。原生錄製測試確認 209 tick 只有 2～3 次定期記錄，另保存一次死亡終幕。

另外以 49 模組、兩個隱藏 Xvfb 客戶端、原生 1920×1080、視距 6／模擬距離 5，透過本機 TCP 代理模擬上傳上限 2 Mbit/s、下載上限 64 Mbit/s及每批最多 8192 bytes 額外 10 ms延遲。第一人稱連線持續 193 秒，收到 12 次連線確認，最大往返約 365 ms。0.7.2 在同類受限傳輸下約 30 秒逾時，暫停第一人稱影像後可持續連線。這是本機代理測試，尚未替代朋友電腦上的實際 Radmin VPN 重測；本版取樣頻率已依設定調整，不能將此結果當作同等錄製負載的 FPS 比較。

### 10 分鐘自動存檔，背景淘汰舊世界副本

自動存檔預設 **12000 tick＝10 分鐘（20 TPS）**；只有持有者在線時累計，安全 10 秒且生命至少 75% 才保存，危險時延後。沒有玩家手動選擇存檔點。

新回歸點完整寫入、校驗且世界重新載入成功後，背景清理多餘的舊完整存檔，預設只保留最新一份；另保留最近一份回歸前世界供復原，避免每次死亡都累積完整世界。既有世界下次成功開啟、存檔或回歸後也會清理已完成的多餘副本。

- `rbdCheckpointRetention`：保留完整回歸存檔數，預設 1、最少 1。
- `rbdFailedWorldRetention`：保留回歸前世界備份數，預設 1，可設 0。

## 0.7.0：效能與定時自動存檔

定時更新的是死亡回歸所用的**完整世界存檔點**，所有持有者共用。預設每 **10 分鐘在線遊玩時間**更新；所有在線持有者連續安全 **10 秒**、生命至少 **75%** 才會保存。受傷、低血量、燃燒、落下、浸水、閱讀或幻影追獵等危險會延後存檔；沒有持有者在線時不累計。沒有新增玩家手動存檔功能，既有首次綁定與進度節點仍可建立回歸點。

記憶的 JSON／GZIP 寫入及第一人稱 PNG 壓縮移到背景，減少遊戲與渲染執行緒等待。錄製解析度、頻率與無損格式維持原設定；佇列達到預算時等待完成，保留完整影格。另減少重複實體掃描與相同資料重寫，並在完整校驗後重用未變動的快照檔案。執行中的世界檔案始終與快照獨立。

完整世界存檔仍會短暫暫停世界運算，玩家保持既有連線；暫停時間受世界大小、磁碟及其他模組影響。背景處理仍會使用 CPU 和磁碟，不代表任何場景都沒有卡頓。

新增以下 **7 項遊戲規則**，可在建立／編輯世界的「遊戲規則」畫面設定：

| 規則 | 預設 | 用途 |
|---|---:|---|
| `rbdAutoCheckpoint` | `true` | 啟用定時自動回歸存檔 |
| `rbdAutoCheckpointIntervalTicks` | `12000` | 自動存檔間隔，20 TPS 下為 10 分鐘 |
| `rbdAutoCheckpointSafeTicks` | `200` | 連續安全期，20 TPS 下為 10 秒 |
| `rbdAutoCheckpointMinHealthPercent` | `75` | 最低生命百分比 |
| `rbdMemoryWriteQueueMiB` | `64` | 背景記憶寫入待處理資料預算 |
| `rbdClientImageQueueMiB` | `64` | 客戶端 PNG 壓縮待處理資料預算 |
| `rbdReuseSnapshotFiles` | `true` | 重用未變動快照檔案，下次開啟／回歸後生效 |

佇列預算不是整個 JVM 的記憶體上限；單一影格超過預算時仍會保留完整影像。TPS 降低時，自動存檔與安全期的實際時間會延長。舊版快照與死者之書格式可繼續讀取。

## 絕望的幻影

持有者的瘴氣預設達到 **10** 後，經過警告便會出現「絕望的幻影」。它複製目標當前的完整物品欄、裝備與 Curios 飾品，保留物品元件；複製品不會掉落。幻影會依玩家成長與觀察到的戰鬥習慣調整追擊，學習記錄保留跨回歸，並可追入其他維度。

生命降到一半進入二階段，回復至 75% 生命並隨機獲得一項加成。預設 **3 秒警告後**，殺戮光環每秒處決半徑 **32 格球形範圍**內除鎖定目標和幻影自身以外的生物，包含隊友、寵物及其他 Boss；圖騰與取消死亡的救命效果無法阻止這項處決。其他持有者被處決時仍可觸發全世界回歸，玩家維持原有連線。擊敗幻影預設降低 5 點瘴氣。

幻影共有 **47 項原生遊戲規則**，可調整生成門檻、警告、光環範圍與間隔、隨機加成、學習速度及裝備使用。已實測騎士原生武器、Curios／Artifacts 飾品及暮色跨維度追擊；要求特定玩家身分或客戶端按鍵的第三方技能仍需個別適配。

## 安裝與回歸

客戶端和伺服器都安裝同版本的 `rbd-0.7.6.jar`，並移除舊版。首次進入單人世界會自動授予死亡回歸並建立初始回歸點；聊天訊息提供書庫座標。Esc 退出閱讀，F8 降低感官刺激。

專服直接使用 NeoForge 原有啟動方式即可。回歸在同一個伺服器程序內完成，保留玩家既有連線；世界暫停、存檔還原後繼續遊玩，不需 supervisor，也不需重新登入。耗時磁碟工作期間仍維持網路心跳。

完整備份需同時保留世界目錄及外部回歸資料：預設位於世界同層的 `.rbd/<世界名稱>/`，例如單人的 `saves/.rbd/<世界名稱>/`。升級後請勿直接以舊版讀取新存檔。

從舊版 supervisor 專服升級時，先正常停止伺服器與 supervisor，再用原始碼包內的工具轉換一次：

```sh
python repository/supervisor/migrate_connected.py --world /path/to/world --control /path/to/old-control
```

工具驗證並複製完整舊檔案至預設位置，保留原本的回歸點、記憶、權能和死亡分支；不覆蓋既有目的地。有未完成交易時需先以舊工具復原。完成後移除舊 supervisor 啟動方式，直接啟動 NeoForge；新版單人世界不需此轉換。

## 遊戲規則

建立世界的「遊戲規則」畫面可設定 **106 項 RBD 規則**。既有世界可從「編輯」→「遊戲規則」修改；多人服也能使用原生 `gamerule` 指令：

```mcfunction
gamerule rbdMaxHolders 2
gamerule rbdAutoBindOnJoin true
gamerule rbdAutoCheckpoint true
gamerule rbdAutoCheckpointIntervalTicks 12000
gamerule rbdCheckpointRetention 1
gamerule rbdFailedWorldRetention 1
gamerule rbdMemoryDeathDwellSeconds 4.5
gamerule rbdCheckpointAdvancements "minecraft:story/enter_the_nether,minecraft:end/kill_dragon"
gamerule rbdPhantomMiasmaThreshold 10
gamerule rbdPhantomAuraRange 32
gamerule rbdPhantomEnabled true
gamerule rbdPhantomRangedMinDistance 6
gamerule rbdPhantomRangedMaxDistance 14
gamerule rbdPhantomDodgeCooldownTicks 30
gamerule rbdPhantomPathIntervalTicks 8
```

涵蓋權能人數、角色與聲音記錄、影像解析度和間隔、感知、瘴氣、告知禁忌、書庫生成、閱讀條件及感官演出。小數與進度清單可直接在原生畫面編輯；清單留空可停用進度回歸點，初次覺醒仍建立起點。

RBD 規則按世界保存、同步至客戶端，設定變更會保留跨回歸。舊 `rbd-common.toml` 提供尚未設定對應世界規則時的初始值。玩家個人的感官強度及 F8 簡化效果仍可調整。

持有者預設 1 名，0 表示人數不限。調低上限只阻止新授權，不會撤銷既有資格。專服主控台使用 `rbd bind PlayerName`、`rbd unbind PlayerName` 或 `rbd unbind_uuid <UUID>`；`rbd status` 查看狀態。

## 多人與模組

任一持有者真正死亡，全服共同回歸；一般玩家死亡不觸發。每名持有者保留各自的記憶，同 tick 多人死亡各自封書、合併為一次世界還原。一般死亡時，原版免死圖騰與成功取消死亡的模組救命道具優先生效；幻影的殺戮光環使用上述處決規則。

已測試騎士工藝 **1.1.3**、暮色森林 **4.8.3345**、GeckoLib **4.9.2**、Player Animation Library **1.1.4** 合裝，包含多人連線、跨維度、變身裝備、模組附件、Boss、容器和進度的回復。詳細涵蓋範圍以原始碼中的實機測試為準，並非所有形態、任務和整合包都已驗收。

0.6.1 以兩名實際客戶端通過 **41 項整合檢查**，涵蓋騎士武器發射、飾品原生效果、暮色首領處決、跨維度追擊、學習記錄與光環觸發回歸後維持連線。0.6.1 的 **18 項實機 AI 檢查**已驗證原生射擊、退距、箭矢閃避、繞牆，以及實際鍵盤移動和持盾的應對。

0.7.0 通過 **18 項 NeoForge GameTest** 及 Java 自測；兩個實際客戶端載入 48 個模組的 LAN 測試通過 **13 項檢查**，涵蓋自動存檔停用、危險延後、安全後保存、真正死亡回歸、世界方塊及兩人的背包／經驗還原，以及第一人稱記憶保存。兩人全程保留原本連線，登入次數各為 1。本輪沒有逐一重測所有騎士形態、飾品效果或暮色 Boss；上述 0.6.1 檢查是先前版本的驗證結果。

世界目錄內的存檔整體還原。一般維度、實體和玩家使用原生載入與同步流程；模組若另外保留 JVM 快取、外部資料庫或跨服狀態，可透過 `WorldReturnEvent.Before/After` 整合。回歸點與執行中的資料包不一致時會暫停還原，保留連線並記錄原因。
